# regimeBlend 선택·검증 실패 조사

2026-10-13 00:46:44 UTC 연구 출력의 `chosen=regimeBlend`는 **과거 선택 구간에서 오차 점수가 작은 진단 후보**라는 뜻이었다. 실제 채택은 없었다. 같은 날 기록된 `passed=false`, `liveForecastChanged=false`, `usedForTrading=false`와 운영 registry의 승격 이벤트 0건을 확인했다.

이번 Draft는 선택·검증·적용 경계를 보강한다. 후보의 수치 예측을 만드는 `fit`·`predict`, 기본 HGB 모델, TOP3와 매매 규칙은 바꾸지 않는다. 기존 실패 결과를 성공으로 다시 표시하지 않으며, 새로 학습한 모델이나 새 실전 성적을 제시하지 않는다.

## 2. 왜 실패 후보가 선택됐나

기존 선택은 앞선 완료 표본에서 `MAE + 0.25 × p90 수익률 오차`를 두 후보끼리 최소화한다. MAPE, 방향 정확도, 하락 포착, 기준 모델을 유지하는 선택지는 고려하지 않았다. 두 후보가 모두 나빠도 한 후보 이름은 반드시 기록된다.

| 선택 표본 점수 | PR #53 | 최신 |
|---|---:|---:|
| biasCorrected | 27.5358 | 33.7182 |
| regimeBlend | 29.3107 | 30.6744 |

점수의 단위는 수익률 %p다. 최신 선택 원점은 2023-04-04와 2023-10-04이며, 선택 결과 완료일은 2024-04-05, 후반 시작일은 2024-10-04다. 2024-04-05 원점의 목표일은 후반 시작일과 같아 `targetDate < evaluationStart` 조건으로 선택에서 제외됐다. 후반 성적이 후보를 선택한 흔적은 없었다.

최신 선택 단계에서도 regimeBlend의 MAPE 17.0347%는 가격 불변 16.6499%보다 나쁘고, 방향 정확도 56.0729%는 기존 64.0688% 및 항상 상승 65.2834%보다 낮았다. 하락 포착률은 0%였다. 오차 점수가 가장 작다는 이유만으로 이름을 선택한 것이 문제다. 새 공동 선택 규칙으로는 **두 스냅샷 모두 selectedCandidate=null**이다.

## 4. 혼합식의 실패 메커니즘

최신 전 평가행에서 local regime fit을 사용할 수 있었다. 전체 날짜 가중 평균 혼합 비중은 기존 모델 32.8524%, 가격 불변 33.8797%, 추세 33.2679%이고, 추가 blendBias는 로그수익률 +0.0265953이다. 기존 예측의 하락 크기가 약 1/3로 줄어든 상태에서 양의 보정이 더해지면서 중립·상승 쪽으로 이동하는 사례가 많아졌다.

원래 하락 경고 745개가 혼합 후 114개로 줄었다. 실제 하락 836행 중 맞힌 하락은 기존 298개, 혼합 50개였다. 혼합은 잘못된 하락 경고도 줄였지만, 이것만으로 하락 포착 향상이라 볼 수 없다. 방향이 바뀐 1,160행 가운데 기존 정답→오답 310행, 기존 오답→정답 206행이었고, 날짜 가중 순손실은 방향 정확도 -5.19194%p와 일치한다.

고정 요소 제거 실험은 원래 fit의 값을 재생해 구성했다. 별도 후보 학습·파라미터 탐색·재선택에는 사용하지 않는다.

| 요소 진단 | MAE (%p) | MAPE (%) | 방향 (%) | 하락 포착 (%) |
|---|---:|---:|---:|---:|
| 실제 regimeBlend | 23.981 | 21.626 | 35.790 | 5.970 |
| local 대신 pooled blend | 24.126 | 21.677 | 35.941 | 5.731 |
| blendBias 제거 | 24.201 | 21.201 | 26.932 | 21.004 |
| 기존 예측에 local blendBias만 추가 | 22.757 | 21.054 | 43.544 | 32.222 |

pooled-only도 비슷하게 실패해 local 구분 자체만의 문제로 볼 수 없다. bias를 제거하면 하락 포착은 늘지만 전체 방향 정확도가 더 나빠진다. 기존 예측+bias는 MAE·방향 일부가 좋아져도 MAPE와 하락 포착이 악화되고 항상 상승을 이기지 못한다. 따라서 이 진단 결과로 새 배합을 고르지 않는다.

## 5. 선택·검증·운영 적용 경계의 수정

| 단계 | 기존 경로 | 이번 Draft의 경계 |
|---|---|---|
| 연구 진단 후보 | 앞선 MAE+0.25*p90 최소화로 항상 한 후보 chosen | legacy chosen 유지, 부적격이면 chosenScope=diagnostic-only로 명시 |
| 공동 조건 후보 | 선택 단계에는 별도 자격 구분 없음 | 가격·방향 공동 조건 먼저 검사, 적격 후보만 selectedCandidate; 없으면 null |
| 후반 통계 검증 | 평균·큰 오차·일관성·방향 검사 | 기존 조건에 MAPE·가격 tail·균형 정확도·하락/상승 포착·하락 정밀도·오경고 조건 추가 |
| 실제 연구 기본값 승격 | paired_gate는 eligible:false를 보지 않고 미래 가격 조건만 판단 | completed-error-adapter-v1 전체 namespace 승격 차단, 오차 조건 통과는 priceScreenPassed로만 기록 |
| 이미 어댑터로 오염된 registry | 그대로 현재 모델에 사용될 수 있었음 | 파일을 쓰기 전에 중단, 자동 수정/복구/승격 없음 |
| 현재 차트 적용 | promoted 표지만으로 연구 기본값을 교체할 수 있음 | 같은 어댑터 namespace 차단, true eligibility/promotion 표지도 우회 불가 |

현재 registry 이벤트는 0건이며 운영 기본 모델을 변경한 사례는 확인되지 않았다. 다만 기존 `build_decision_support.py`는 12개 비중첩 공개 원점·30쌍·평균 MAPE 5% 개선·날짜 승률 60%·tail/최근 조건·최신 자체 interval을 통과하면 registry를 자동 변경하는 경로가 있었다. 이 함수는 과거 연구 실패나 PIT 공백, 방향 정확도를 조건으로 사용하지 않았다. 따라서 현재 `eligible:false`/`automaticPromotion:false` 표시만으로 향후 적용이 영구 차단됐다고 말할 수 없었다. 이번 수정은 그 어댑터의 입력 자격 경계를 막는다. 기존 **다른 모델**의 수치 승격 조건, TOP3 및 실제 매매 엔진은 유지한다.

새 공동 규칙은 오차의 개선과 방향의 악화를 서로 상쇄해 점수화하지 않는다. MAE는 모든 기준 대비 2% 개선, MAPE와 두 tail은 모든 기준 대비 악화 없음, 방향은 기존/항상 상승 이상, 균형 정확도·상승/하락 recall은 기존 이상, 실제 하락 20건 이상일 때 recall 최소 10%, 하락 precision은 기존/유병률 이상, false-down rate는 기존 이하를 요구한다. 모두 앞선 완료 선택 구간에서 검사한다. 기준은 이번에 이미 본 결과로 성능을 주장하기 위한 최적화 값이 아니며, 보수적인 차단 정책이다.

모든 통계 검사가 true인 합성 사례도 productionEligible=false다. 연구 어댑터 namespace는 PIT·원래 발표/가격 빈티지·종목 생애주기 검증과 별도 검토된 프로토콜 변경 전에는 해제할 수 없다. 공개 예측 수집과 연구 성적 추적은 계속 가능하다. false 후보를 삭제하거나 성공 종목만 남겨 평균을 개선하지 않는다.

## 6. 데이터 누출과 남은 PIT 공백

확인된 시간 경계: 원래 HGB의 train/calibration targetThrough < origin, 보정 fit의 모든 이전 날짜 블록 targetDate < origin, 선택 targetThrough < 후반 시작, 예측 범위에 쓰는 과거 어댑터 오차 완료 조건, 비중첩 수익률 창이다. 수익률 창은 (origin,target]이므로 경계 종가를 공유하는 것은 허용하되, 같은 targetDate를 가진 당일 완료 결과를 이전 완료 자료로 취급하지 않는다.

뒤쪽 y/다른 후보 예측을 바꿔도 선택은 바뀌지 않으며, targetDate >= 특정 origin인 y를 바꿔도 해당 origin의 pooled/local 보정은 바뀌지 않는다. 후반 성적을 보고 후보나 threshold를 교체하지 않는다. 후반의 한 평가 결과가 완전히 성숙한 후 다음 원점의 고정 온라인 보정식에 들어가는 것은 기존 walk-forward 설계이지, 모든 후반 원점을 동일한 한 번의 학습으로 예측한 untouched holdout은 아니다.

중복 키·중복/누락 source fold·어느 후보의 누락/비정상 예측·겹친 날짜 블록·미완료 source target·보정 완료 경계 위반·비유한 metric은 전체 비교를 실패시킨다. 후보별 불리한 행만 누락해 비교할 수 없다. ±2% 경계는 로그값에서 비교해 정확한 0.98/1.02 endpoint를 중립으로 유지한다.

위 시간·해시 검사는 완전한 PIT 입증이 아니다. PR #25 head `1aa16f7a831b0aeed411593fe64464af94115cd5`의 PIT 입력 감사와 합병/상장폐지 생애주기 감사를 그대로 재사용했다. **PIT 0/34, 생애주기 0/34, 실제 생애주기 계산 결과 0건**이다. 당시 membership/sector, 영구 security ID·dated alias, 원래 knownAt/effectiveAt와 revision vintage, 수정 전 가격 vintage, 제거/상장폐지 종목의 전체 outcome 및 확정된 합병/주주 권리 자료가 여전히 부족하다. 최신 원점들도 인증 자료를 추가하지 않았다.

같은 현재 구성 종목을 과거로 가져간 생존편향은 유지되며, 파일 hash가 맞고 sourceIntegrity.passed=true여도 이 공백이 해소되지 않는다. PR #25의 export/training 차단과 PR #53의 모든 기존 결과는 변경하지 않았다. 새로운 학습 성과·실전 적격 결과는 없다.

252거래일은 원래 검증 2,471행·5개 source fold가 있지만 역사적 각 원점에서 먼저 완전히 성숙한 이전 원점은 최대 3개였다. 보정 fit은 4개를 요구하므로 보정 검증 행은 0개이며 독립 후반 평가를 할 수 없다. 5개 source fold를 5개 보정 검증으로 잘못 세지 않는다.
