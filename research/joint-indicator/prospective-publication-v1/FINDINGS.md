# 21거래일 연구 발행 복구

## 원인과 선택

실제 main 발행 경로와 아카이브를 연결해 확인했다. 입력 감사의 기준 main과 파일 해시는 `publication-path-audit.json`에 있다.

- 환경 연구는 `update-environment-research.yml` → `build_environment_research.py` → `research/issued.json`으로 이어진다. `dcc1e9ca`에서 v5를 도입했으나, 2026-09-13의 `038c8116`에서 v6의 126·252거래일로 전환하면서 21거래일 프로필을 제거했다. 현재 코드는 v7이다. 원래 v5 21거래일 501행의 마지막 기준일은 2026-09-11이다.
- 단순 추세는 `update-eod-prices.yml` → `build_forecasts.py` → `forecasts/archive/YYYY-MM.csv`로 이어진다. 같은 `038c8116`에서 v1의 21·84·252거래일이 v2의 126·252거래일로 바뀌었다. 원래 v1 21거래일 1,509행의 마지막 기준일은 2026-09-11이다. 최근 EOD 및 후속 연구 Actions는 성공했으므로, 새 21거래일 행의 부재를 현재 EOD CI 실패로 설명할 수 없다.
- 기존 동결기와 프로토콜은 Draft PR #25에만 있다. 기존 동결 워크플로는 main을 checkout하므로, 이 초안 자체는 배포된 수집 경로가 아니다. 또한 동결기는 사전등록 당시 main의 후손인 입력 커밋을 요구한다.

21거래일 v5의 `horizonModel`은 `z` 가격·시장 문맥과 두 개의 regime 플래그를 사용한다. SEC/실적의 `w` 필드는 이 프로필의 추정에 사용되지 않는다. 따라서 당시 소스를 고정하고 신규 데이터로 원래 추정기를 다시 학습하는 복구 경로를 구현했다. 기존 fitted model을 되살린 것으로 표현하지 않는다. 126·252거래일을 원래 연구에 대입하거나 별도 장기 연구를 사후 생성하지 않았다.

## 실행 경계

`research/prospective-21-issues`는 최신 main에서 시작하는 별도 수집 브랜치다. 여기에 원래 프로토콜·동결기·검증기와 새 발행 코드만 복사한다. PR #25는 Draft 상태를 유지한다. 홈페이지, TOP 3, 운영 예측·순위·매매 규칙에는 쓰지 않는다. main에 필요한 배포 변경은 별도 수집 브랜치를 checkout하는 일정 실행 파일 하나뿐이다.

원래 프로토콜의 review-before-capture 조건을 유지한다. 첫 실행 전 `ACTIVATION.json`에는 검토한 코드 커밋, 파일 해시, 검토 시각과 프로토콜 해시를 기록해야 한다. GitHub 승인이나 사람의 검토가 있었다고 주장하지 않는다. 검토 후 코드가 달라지거나 활성화 기록이 없으면 발행을 차단한다.

매 거래일 마감 후 수집 가능 여부만 확인한다. 첫 구간 이후에는 이전 구간 목표일 전까지 다운로드·학습을 하지 않는다. 5개 비중첩 구간이 동결되면 신규 발행을 멈춘다. 최초 신규 발행 시각은 실제 실행 시각이며, 기준일은 그 시점에 공개된 가장 최근 확정 XNYS 세션이다. 과거 기준일이나 발행 시각을 지정하는 CLI 옵션은 없다.

## 보존하는 입력과 발행 증거

1. main 입력 커밋을 고정하고, 그 커밋의 `research/universe.json`과 `prices/latest_prices.csv` 원문을 복사한다. 전체 가격 기준일이 가장 최근 확정 세션과 일치해야 한다.
2. v5용 20년 조정 가격을 새로 수집한다. 원문 압축 파일, 원문/압축본/정규화 해시, URL·검색 시각, 증권명 확인과 누락 목록을 보관한다. 이전 캐시로 대체하지 않는다. 모든 시장 문맥과 최소 450개 구성종목 가격이 없으면 아무 예측도 발행하지 않는다.
3. `legacy/`의 원래 Git blob 5개는 `dcc1e9ca87b3d8353cff0b2077ae8ee429006c2a`와 바이트 단위로 일치한다. numpy 2.2.6과 scikit-learn 1.8.0을 고정한다. 별도 프로세스가 당시 `records`, `fit_horizon`, `predict`만 사용한다. 금요일 학습 origin, CIK 중복 제거, `trainTargetDate < origin`, 원래 모델 파라미터와 방향 절단 규칙을 유지한다. 원래 `build()`나 실서비스 발행 함수는 호출하지 않는다.
4. 단순 추세 v1은 main에 실제 공개된 원래 Close·수익률·변동성 행에 당시의 `predict(row, 21)`을 적용한다. v5의 조정 가격과 추세의 Close 기준을 섞지 않는다. 각 구성요소의 앵커는 따로 저장하며, 혼합 시 원래 프로토콜의 공통 앵커 규칙을 그대로 적용한다.
5. 실제 생성 완료 시각, 모델 버전, 소스·입력 해시와 행별 해시를 저장하고, 수집 브랜치에서만 `research/issued.json`과 해당 월 추세 아카이브에 추가한다. 기존 행과 첫 발행은 덮어쓰지 않는다. 원문·정규화 입력·발행 manifest를 같은 커밋에 넣는다.
6. 이후 **변경하지 않은** `freeze_prospective_blends.py`가 커밋된 HEAD만 읽는다. 다음 커밋에 후보 예측을 동결하고 `verify_issue_artifact`로 원본 행·해시·Git 최초 등장·타깃 전 시각을 검증한 뒤 fast-forward push한다. main push, 강제 push, 자동 승격은 없다. 입력 커밋 이후 중단되면 다음 실행이 동결을 먼저 복구한다.

## 검증 및 해석

새 테스트는 실제 HGB 학습의 반복 재현, 원래 코드 바이트, 조정/Close 구분, 미래·오래된·중복·다른 증권의 입력 거부, 대상 브랜치·쓰기 경계, 첫 발행 보존, 재실행, 모델/기간 바꿔치기 거부를 검사한다. 임시 Git 저장소에서는 신규 구성요소 → 원래 동결기 → 최초 등장 검증을 끝까지 실행한다. 테스트 행은 합성 fixture이며 원격 시장 발행이나 연구 성능의 증거로 사용하지 않는다.

실제 첫 발행과 원격 CI의 결과는 실행 이후 별도의 운영 검증 기록에 추가한다. 테스트 통과만으로 실제 수집 성공이나 혼합 성능 개선을 주장하지 않는다. 원래 사전등록 5개 전체 구간이 미래에 완성되기 전까지 점수·모델 선택·승격은 없다.

현재 구성종목 선택, 수정 가능한 조정 가격의 학습 이력, 상장폐지·합병 종목의 미래 목표 가격 누락 문제는 그대로 남는다. 동결한 전체 교집합 중 하나라도 목표 증거가 없으면 기존 평가기가 집계를 차단해야 한다. 미래 평가는 각 목표일 후 main에 실제 등장한 `ml/archive/YYYY-MM-DD-pooled-hgb-pattern-v3-medium-long.json`을 소스 커밋·원문 해시·최초 등장 시각과 함께 수집 브랜치에 보존한 뒤 기존 검증기로 수행해야 한다. 현재 결과를 보고 가중치나 대상 종목을 바꾸지 않는다.
